# 当前可用性评估与最小收尾计划

评估日期：2026-09-08。对象：当前工作区 S0–S8 实施后的代码。本轮目的是判断能否投入使用，不启动下一轮大规模重构。

## 1. 决策结论

**当前项目可以作为有人工复核的文档排版与材料装配工具投入试运行。建议停止扩大改动范围，完成版本留存和目标文档首件验证后使用。**

本轮复测未再复现此前五类核心问题，真实 Word 构建、内容与格式阻断、失败保留旧成果均有新执行证据。继续使用的主要前提是人工确认格式识别结果，并检查最终 Word/PDF。现有证据不足以承诺任意学校论文模板均可无人复核直接交付。

这是一项限定范围的可用性判断，不等于所有历史计划条目已完全验收，也不等于发现了必须立即重构的生产缺陷。

## 3. 当前使用范围

| 场景 | 建议 | 使用条件 |
| --- | --- | --- |
| 常规报告、材料包、明确格式的 DOCX | 可以使用 | 按现有来源策略和格式包构建，最终人工复核 |
| 参考样例识别格式，再应用于其他文档 | 可以使用 | 审核标题层级、正文、字体字号等候选；确认待审项并冻结格式包和角色映射 |
| 原样保留或混合排版，包含图片、页眉页脚、脚注尾注 | 有条件使用 | 首件验证实际输入中的复杂对象及分节；失败门禁必须保持启用 |
| 某个具体学校的论文 | 先做该模板首件验证 | 对照学校要求检查前置部分、目录、页码、摘要、参考文献和分节，再决定是否交付 |
| 任意论文模板的全自动规范交付 | 暂不承诺 | 当前测试覆盖不足，不能由通用样例推出全部学校模板兼容 |

剩余的明确覆盖缺口：`tests/test_remediation_word.py` 的 SW03 仍断言部件为 `cover/toc/body`，声明和摘要位于正文中；`docs/acceptance/create_complete_thesis_fixture.py` 的 Abstract 使用与中文部分相同的中文合成段落。因此，独立前置选区、真正的英文摘要及其独立格式与页序还没有被这个“完整论文”测试充分证明。该缺口不阻止常规报告使用。

## 4. 下一步只做最小收尾

### U1：留存可复现版本——首次正式使用前完成

当前工作区有大量已修改和未跟踪文件。由维护者检查并提交本次实现及必要资源，尤其是新增 `lib/`、`schemas/`、`formats/`、测试与示例文件；不要把个人输入或生成成果顺手加入版本库。本次评估未代为提交这些用户修改。

同时记录 Python、依赖版本、macOS/Word 版本及实际 Word 权限环境，留存使用的 manifest、格式包和角色映射。验收标准：另一份干净检出具备全部运行资源，可以执行示例计划与环境检查；如不做干净检出复测，明确保留“仅当前机器验证”的限制。收尾期间不升级依赖、不改核心架构。

### U2：目标文档首件验证——首次对外交付前完成

选择一份近期真实要交付的文档及其参考格式，用副本执行。沿用 [custom-format-demo 操作说明](../examples/custom-format-demo/README.md) 的分析、人工确认、编译、映射流程，再按 `--plan → --doctor → build → smoke` 顺序运行。替换成真实输入路径及 manifest，不复用绑定其他源文件哈希的 RoleMap。

人工检查最终 Word 与 PDF：标题层级和字体、正文与段距、目录页码、图片表格、脚注尾注、页眉页脚与分节。论文额外检查声明、中英文摘要、前置页码和参考文献。记录输入/配置版本、输出路径、检查人和结论。

验收标准：门禁通过，内容无缺漏或重复，关键页面符合本次交付要求。通过后开始使用；此步骤针对目标模板执行一次首件验收，后续交付继续做必要人工复核，不要求每次重跑所有研发测试。当前未提供目标交付文档，本轮不把该步骤记为已完成。

### U3：校准对外说明——与首件验证一起收尾

只做文档小改：在 `docs/formatting-capabilities.md` 顶部标明当前 S 阶段和本报告入口，将旧 N 阶段结果标为历史记录；把“完整论文已验证”限定为实际已覆盖场景，并明确人工确认与最终审阅要求。验收标准：README、能力说明和验收状态不再让用户误以为任意论文模板均可自动交付。

### U4：仅近期需要复杂论文时补一个专项用例

优先补 `docs/acceptance/create_complete_thesis_fixture.py` 和 `tests/test_remediation_word.py`：增加真正的英文摘要，使用现有选区/部件能力将前置部分独立装配，检查部件顺序、选区不重不漏、摘要字体以及分节页码，并在 Word 导出的 PDF 中检查对应页面。

先补验证，只有该用例复现实际阻塞时才修改对应模块。若近期不交付这种论文，本项延期。若发现超出当前能力的模板要求，可以人工在 Word 中完成最后调整，保留自动产物与人工最终版，并对人工最终版重新审阅；不得把人工改后的文件沿用为自动门禁已验证产物。

## 5. 停止条件与延期事项

完成 U1、U2，并校准 U3 的说明后，冻结当前版本进入使用与问题收集。仅有真实需求触发 U4。当前没有依据要求再启动全量重构、新一轮通用格式引擎设计或扩大 AI 自动决策范围。

暂缓新增复杂模板类型、评估平台扩建、批量自动交付和大规模模块拆分。只有实际文档出现内容丢失/重复、格式错误未被阻断、旧成果被破坏等问题，才暂停相应场景并做最小修复及对应回归。不要因为其他尚未使用的场景缺少测试而无限延迟当前可用范围的上线。

本轮只新增评估文档与审计证据，没有修改生产代码。
