**验收不通过。当前不能把 B1–B10、M1 或 M2 标记为全部完成。**

## 已确认问题及修复验收条件

以下 P1 均应在声明 M1/M2 支持前解决。P2 是需要补齐的依赖、交互或验证缺口。

### F01 · P1 · 选区切片丢失图片关系与自定义样式

位置：`lib/document_parts.py:208–242`，尤其是 `Document()` 后只 deepcopy 内容 XML；`lib/composition.py:301–307` 使用该结果作为新部分。

复现：源段落包含图片和 `AuditCustomStyle`；选取整个段落装配为 `main_text`。结果没有 media 部件，也没有源样式；图片的 `rId9` 在新文档中实际指向 `footer1.xml`。`validate_delivery_structure()` 仍返回成功。观测键 `region`。

影响：论文图片可能缺失或损坏，源样式失效；即使后续装配使用 PackageImporter，也无法恢复在切片时已丢掉的部件。

修复：切片必须通过统一 OPC 导入器导入选中内容及其关系闭包，重映射样式、编号、书签、批注/脚注等关联 ID；不能只复制正文 XML。结构校验同时检查关系类型和目标内容类型。

验收：选区包含内嵌图、超链接、自定义样式和原生编号，单独导出及与其他部分合并后都能解析；验证图片关系类型、媒体哈希、有效样式与编号语义，并通过 Word 打开/导出检查。

### F02 · P1 · 已检测的格式错误不会阻止发布，未检查项目仍标 passed

位置：`lib/engine.py:542–567`、`:577–578`。

复现：仅替换 Word 交付阶段，把应为 12 pt 的正文改成 70 pt。真实 `verify_delivery_format()` 报告字号不符，但引擎只写 `format_verification=warnings`，最终发布文件。观测键 `format_gate`。

此外，只有单文件且交付部分包含字面量 `body` 才执行完整性与格式检查。多文件来源、`main_text` 等合法自定义内容部分被跳过，初始化结果却仍为 passed。这让 F01 的对象损失更容易绕过最终检查。

修复：每份交付物根据 BuildPlan 的实际选区和角色执行验证；初始状态为 not_run，只有完成校验才能 passed；托管属性不符合配置必须抛错并阻止发布。汇总全部交付物的问题，不能被后一份结果覆盖。

验收：对单 DOCX、多文件、自定义部分分别注入文字/媒体损失及格式错误，均退出失败；原已发布成果和元数据保持不变；明确区分未验证能力与已验证失败。

### F03 · P1 · 显式角色映射和 preserve 策略未接入引擎

位置：`lib/engine.py:481–487`、`:515`、`:535`；`lib/config.py:578`。

配置将策略保存在 `config.formatting`，引擎却从 `config.resolved_format.policy` 读取；RoleMapper 也没有读取 `formatting.role_map`。

复现一：声明首段为 heading.2、映射哈希为全零，实际仍按 SynthBody 处理且标题节点数为 0，过期文件也没有被拒绝。该反例直接证明映射文件没有经过规定的读取/校验流程，不声称这个故意过期的映射应当被应用。观测键 `mapping`。

复现二：`mode=preserve,page_policy=source` 的 Normal 段落变为 SynthBody，30 mm 下边距变为 24.606 mm，原页脚 `ORIGINAL FOOTER` 被替换为旧页码模板。观测键 `preserve`。

修复：在准备 BuildPlan 时加载并校验映射版本、源哈希和 NodeRef，显式映射优先于推断；传递真实 FormattingPolicy。在任何修改前确定 preserve/restyle/mixed 的接管边界；v3 保留区不得进入旧全局标准化流程。

验收：有效映射改变导航标题与样式；错误哈希在创建工作目录前失败；preserve 的文字、对象、有效样式、页面和页眉页脚不变；mixed 只改变声明接管的属性。

### F04 · P1 · 多文件和页面/目录仍使用旧公文规则

位置：`lib/engine.py:523–535`；`lib/composition.py:139–194`。

复现：目录来源使用 v3 格式包，把 heading.1 改为 37 pt，实际生成标题仍为 16 pt。主流程仍把 `config.fonts` 传给旧递归渲染器，没有传入新 RenderContext。观测键 `directory`。

单 DOCX 分支没有应用目标页面尺寸，却调用旧分页与页脚标准化；A4 预设的 Word 导出前 DOCX 仍为 Letter。目录标题和条目也仍通过旧尺寸/字体接口生成。

修复：统一单文件、多文件、目录、页眉页脚和分节的格式上下文；旧标准化仅由兼容策略显式调用。根据当前节规格应用纸张、边距、页眉页脚与图片/目录几何。

验收：同一源分别应用 report/academic/自定义包，检查生成标题、正文、目录和各节；覆盖 A4、自定义尺寸、横转竖、目录和多来源，保证实际有效属性来自配置。

### F05 · P1 · 页码校验记录错误但不拒绝

位置：`lib/delivery.py:103–118`、`:148–159`；有意空白页规则位于 `:131–139`。

复现：配置 upperRoman 从 1 开始，向真实校验器提交正文编号 7、后续标题编号 9、PDF 观察标签均为 999 的测量记录。函数成功返回，两个 `label_verified` 均为 false。观测键 `page_validation`，其中 PDF 和测量值为故意构造的测试输入。

原因：存在自定义序列时跳过旧编号断言，但没有替代的序列验证；标签比较只写布尔值。标题格式还会落到第一个 content 部分，不能可靠代表所属节。oddPage 的白名单会覆盖两个部分之间所有偶数页，范围过宽。

修复：依据节点所属部分/节，验证起始值、连续性、重启、显示格式与隐藏规则；标签不匹配或无法完成必要测量时禁止发布。空白页豁免只允许有明确分节证据的插入页。

验收：真实 Word 样本覆盖罗马→阿拉伯、重启、同名标题、横版继续及奇数起章；错误标签、额外空白页和错误 restart 必须有负向测试，且均阻止发布。

### F06 · P1 · 字段更新存在异常、错误引用范围和参数类型冲突

位置：`lib/field_updater.py:75–88`、`:138–139`、`:190–197`；`lib/delivery.py:198–218`；`lib/composition.py:363–364`。

已复现三个相互独立的问题：

- `SEQ Figure \\* ROMAN`、`SEQ Figure \\* ALPHABETIC` 给转换函数传入不存在的 `lower` 参数，触发 TypeError。
- 书签只包围题注序号，REF 却返回整个段落 `Figure 0 Caption outside bookmark`；正确值应为更新后的 `1`。代码按整段提取并在 SEQ 更新前缓存。
- delivery 的页码 guess 值为字符串/整数，FieldUpdater 的 PAGEREF 却假设值为字典并调用 `.get()`；有匹配书签时会触发异常。无目录时还需补测 PAGEREF 的测量后更新路径。

观测键 `seq`、`ref`、`pageref_with_delivery_guess`。

修复：统一 PageRecord/标签接口；按字段依赖顺序更新，按 bookmarkStart/bookmarkEnd 精确提取范围；明确支持的开关和故事范围，无法支持的受控字段应诊断。字段值更新后重新测量实际待发布 DOCX。

验收：简单/复杂 SEQ 混排、大小写罗马与字母、前向/后向 REF、仅包序号及跨段书签、带/不带目录的 PAGEREF 全覆盖；对比 DOCX 缓存值和同版本 Word PDF。

### F07 · P1 · 源选区校验可以静默遗漏图片或退回全文

位置：`lib/document_parts.py:188–194`；`lib/composition.py:262–266`、`:301–304`。

复现：未被任何选区覆盖的图片专用段落没有可见文字，因此被认为可以忽略。另一个直接装配探针指定不存在的 `p[99]`，校验异常被吞掉，结果复制源文档全部 5 个段落。观测键 `unassigned_image_accepted`、`invalid_region_at_assembly`。

边界：无效 p[99] 的反例直接调用装配函数，不能据此声称 CLI 前置检查也必然放过同一输入；它说明装配层在校验失败时存在危险回退。图片漏分配则是 SelectionValidator 自身的判定漏洞。

修复：所有实质对象都参与覆盖率判断；根据原始 NodeRef 解析选区并携带稳定映射。删除吞错后的全文回退，选区校验失败必须停止装配。

验收：漏分配的图片、公式、内容控件和字段均拒绝；错位/不存在/重叠的边界不能生成全文副本；只有显式 exclude 的内容允许移除。

### F08 · P1 · 内容完整性校验不检查脚注、字段和链接语义

位置：`lib/content_integrity.py:250–339`。

复现：源文档含脚注关系、脚注定义及正文引用，提取清单后删除脚注引用与关系；正文文字不变，`verify_content_integrity()` 仍返回 true。观测键 `removed_note_accepted_by_integrity`。此反例验证校验器，未经过 Word 全流程。

当前校验主要比较文字、表格、媒体哈希和公式，提取出的其他语义未形成完整门禁；公式集合也不能检出重复公式数量减少。

修复：按实际交付选区比较对象及引用关系，并建立允许变化的明确规则。脚注/尾注须核对引用、正文及关联资源；字段需验证指令、依赖与结果；媒体/公式不仅比较是否存在，还要核对引用次数与位置语义。

验收：独立删除或改坏脚注、尾注、REF、链接、重复公式中的一个实例，必须被发现；合法编号重映射和生成目录不会误报。

### F09 · P2 · 样例工作流与依赖未达到计划的完整交付条件

位置：`lib/format_review.py:15`；`requirements.txt`；`synthesize.py`；`schemas/`。

`format_review` 直接 import jsonschema，但 requirements 没有声明；当前机器已有该包不能证明全新环境可用。分析/决策/角色映射三个 Schema 未提供，计划中的 `preview-format`、`render-preview`、`migrate-manifest` 命令未提供。样例识别命令可以执行，仍不足以满足 B6 的完整流程约定。

另外，`verify_delivery_format()` 用角色名称直接索引 styles（`lib/content_integrity.py:358–391`），没有完整使用 roles→style 引用；分析编译得到不同 style ID 的包需要额外覆盖，不能仅靠内置预设测试推断其验证有效。

修复验收：在干净依赖环境跑样例识别与编译；明确并补齐本轮交付命令，或者正式调整计划和能力表。自动生成包必须走目标映射和真正构建，验证非同名角色/样式引用也被实际检查。

### F10 · P1 · “完整论文端到端验收”没有覆盖生产交付链路

位置：`tests/test_thesis_acceptance.py:209–224` 及后续断言；`docs/formatting-progress.md`；执行计划 B7–B10 状态。

该测试手工构造 `pages`，直接调用 assemble_document；虽然 import 了 build_deliveries 和 inspect_document，实际没有调用。它验证了部分 XML、脚注和题注拼接，却没有运行引擎、真实 Word 分页、PDF 标签比较或最终完整性/格式门禁。因此不能支持“完整论文、真实 Word、全部强制项通过”的声明。

修复验收：保留该测试作为装配级回归，另建真正的 M2 集成测试，从唯一 CLI 入口构建完整匿名论文；保存输入哈希、解析配置、Word 测量与 PDF、元数据，并逐项覆盖执行计划 §13。真实 Word 测试被跳过或环境阻塞时，M2 结果必须为未完成。

## 建议的修复执行顺序

1. **先修发布门禁和对象完整性：F02、F01、F07、F08。** 先确保错误产物不能作为成功结果交付，同时修复已确认的对象损失。每项增加失败注入与发布回滚断言。
2. **接通格式和映射主链路：F03、F04、F09。** 用相同的格式上下文贯穿单文件、多文件、目录与分节，完成样例包→人工决策→目标映射→实际格式验证闭环。
3. **再完成论文功能：F05、F06。** 统一页码记录及字段依赖，先通过确定性的负向测试，再执行真实 Word 样本。
4. **最后重做里程碑验收：F10。** 逐条填写 M1/M2 测试矩阵，附证据并更新进度及能力声明；未测或不支持项保留明确状态。

M1 重验收至少覆盖旧版匿名回归、单 DOCX、目录多文件、自定义格式、样例编译包、preserve/mixed、正文/目录/图片/表格和发布失败回滚。M2 在此基础上增加完整论文选区、页码区间、奇偶页眉页脚、脚注/尾注、题注、REF/PAGEREF 与真实 Word/PDF 一致性。
