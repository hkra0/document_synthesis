# 自定义格式与样例文档识别规划

状态：设计建议，尚未实现。调研日期：2026-09-05。

## 1. 推荐方向

将现有引擎逐步改造为“语义结构 + 可复用格式包 + 分节装配 + Word 实际排版验收”。公文成为其中一个预设。用户可以手工配置格式，也可以从样例 DOCX 提取格式、校正角色映射、保存后复用。

核心区别是把两个问题分开解决：样例文档告诉系统“标题应该长什么样”；待排版文档需要独立识别“哪些段落是标题”。样例的段落位置、正文内容和作者信息不应该进入通用格式包。

首个可用版本以可编辑 DOCX、单栏报告和基础论文排版为目标，保留现有材料合成功能。完整学位论文需进一步支持前置部分、分节页码、脚注、题注及交叉引用；不能仅凭换成宋体、小四就宣称支持论文规范。

## 2. 当前实现与具体限制

以下判断基于当前工作区代码，含已有未提交改动。此次只新增规划文件。

| 位置 | 当前行为 | 对通用排版的影响 |
| --- | --- | --- |
| `lib/config.py` | 支持 `page_setup`、`fonts`，严格接受 v1/v2 配置 | 已有扩展基础，但不能表达完整段落样式和分节规则 |
| `lib/styles.py` | 标题字号、段距、行距、目录缩进和制表位硬编码 | 改字体仍无法控制整套格式；目录宽度不能适应不同版心 |
| `lib/styles.py` | 样式合并按同名 ID 替换，部分属性内联；清理主题色、调整长段落行距 | 来源之间会发生样式污染，用户有意设置的颜色和行距可能被覆盖 |
| `lib/highlighted_docx.py` | 标题提取与格式修改耦合；重建标题 run；统一页脚及部分页边距 | 容易丢失标题内局部格式，不适合原样保留论文结构 |
| `lib/renderers.py` | 固定横竖版尺寸与图片最大尺寸，编号转成文本；仍有材料特征专项分支 | 影响自定义纸型、多级编号、复杂表格和通用模板 |
| `lib/composition.py` | 已有前置部分样式/关系重映射；固定封面、目录、正文装配与页脚处理 | 可复用装配基础，但论文不能局限于三种部分 |
| `lib/pagination.py`、`lib/delivery.py` | 书签定位可靠，但打印编号仅整数；正文从 1 连续编号 | 不支持罗马页码显示、多个编号区间；相关 QA 也需要升级 |
| `lib/qa.py` | 空白页、单标题页等启发式检查 | 需区分双面打印有意留白、章节扉页和真正排版缺陷 |

已执行匿名示例 `--plan`，验证当前只读计划仍按“封面、目录不显示页码，正文从 1 开始”工作；此次没有进行 Word 构建或新版功能验收。

## 3. 参考依据与适用边界

1. **Word 原生样式应作为输出基础。** WordprocessingML 支持段落样式、字符样式与继承关系；样式 ID 与显示名称是不同概念。应生成实际样式定义及段落引用，保证用户后续能在 Word 中统一修改。[Microsoft 样式示例](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-apply-a-style-to-a-paragraph-in-a-word-processing-document)、[样式继承说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.basedon?view=openxml-3.0.1)
2. **参考文档复用已有成熟范例。** Pandoc 的 `reference-doc` 使用参考 DOCX 的样式和页面等属性，忽略其正文内容；这支持“格式引用与内容分离”的方向。但它不等价于任意样例自动识别，也不能据此承诺复杂 DOCX 往返无损。[Pandoc 文档](https://pandoc.org/MANUAL.html#option--reference-doc)
3. **样式名称不能成为唯一识别依据。** python-docx 文档说明内置样式在 WordprocessingML 中使用英文名称，样式 ID 也不适合作为跨文件固定身份；项目应建立自己的语义角色标识。[python-docx 样式说明](https://python-docx.readthedocs.io/en/latest/user/styles-understanding.html)
4. **规范需要锁定版本。** 官方平台显示 GB/T 9704-2012《党政机关公文格式》现行；GB/T 7713.1-2025《信息与文献 编写规则 第1部分：学位论文》于 2026-02-01 实施，全部代替 2006 版。标准状态核验不等于已对照全文完成合规实现。[公文标准](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F3CC9BEF482524C895FDA7A08BB4A70E&refer=outter)、[学位论文标准](https://std.samr.gov.cn/gb/search/gbDetailed?id=3B46A026CC84469CE06397BE0A0AEEB8)
5. **论文格式存在机构差异。** 兰州大学公布的范例涉及前置/主体/结尾部分、图表与分区编号；陕西师范大学范例还涉及双语图表题和奇偶页眉。这些发布于 2020、2023 年的文件用于提取需求，不作为 2026 年实际提交的最新依据。[兰州大学范例](https://ge.lzu.edu.cn/xueweishouyu/guizhangzhidu/lunwenguanli/2020/1223/158947.html)、[陕西师范大学范例](https://newyjs.snnu.edu.cn/info/1030/6410.htm)

由这些资料推导的产品建议：通用预设提供起点，学校/期刊格式包记录机构、年份、适用学位或投稿类型、依据链接、已核验规则及未覆盖项。用户选择的提交要求作为验收目标；样例中的格式偏差作为冲突展示，不能静默覆盖要求。现有预设命名为 `legacy-official`，不直接标注“国标完全合规”。

## 4. 用户流程

### 4.1 三种格式入口

- 选择预设：沿用现有材料样式、通用报告、基础学术文档。
- 自定义：按页面、正文、标题、目录、页眉页脚等分组修改；支持中文字号名，内部转换为 pt。
- 选择样例：导入 DOCX，分析实际使用的格式，展示角色映射和代表段落，修改歧义后另存格式包。

仓库当前是 CLI。先提供统一入口下的分析操作、结构化报告和本地可阅读预览，再接文件选择器与表单界面；分析、保存和构建逻辑不依赖 UI，也不为每个项目新增脚本。

### 4.2 样例识别到复用

1. 选择样例及用途；用途只缩小候选角色，不直接套用默认字号。
2. 展示标题、各级标题、正文等候选，以及页边距、页眉页脚、分节概况。
3. 每个候选显示代表段落、出现次数、格式摘要和判断依据。把“观察到的值”和“系统补全的值”分开。
4. 用户可以将某段标为正文或某级标题，调整混用样式，指定空白模板中尚未使用的样式。
5. 生成使用虚构内容的样式预览；保存版本化格式包。重要歧义集中处理一次，普通已明确属性自动采用。
6. 对待排版文件独立分析结构，显示将改变的角色、保留的内容和未识别区域。
7. 应用已保存规则，输出新文件，通过检查后发布。后续相同格式任务直接复用。

人工校正落为显式映射规则，不能只停留在一次对话里。没有确认的结构性歧义不得静默强制排版；非交互模式用预先配置的保留/报错策略。

### 4.3 格式应用范围

| 模式 | 行为 | 典型场景 |
| --- | --- | --- |
| 保留源格式 `preserve` | 保留源样式和内容结构；跨文档导入时隔离引用 | 原始附件、签章材料、复杂图表 |
| 统一排版 `restyle` | 识别角色，按目标样式重排；保留受保护的行内语义与对象 | 报告、可编辑论文正文 |
| 混合 `mixed` | 主文统一，指定文件或区域保留 | 正文排版＋证据附件 |

保留格式不保证在不同字体、页面环境、渲染器中逐像素相同。要求整页视觉固定的附件可继续选择 PDF/图片嵌入；扫描件不会因此变成可编辑正文。样式改写权限与页面/页码接管权限分别配置，避免选择保留模式后仍被页脚标准化覆盖。

## 5. 格式与结构模型

### 5.1 三种独立配置

**项目清单**继续负责输入、顺序、输出和选用哪个格式包；**格式包**负责页面、样式与编号等呈现规则；**文档角色映射**负责将具体输入节点映射为正文、标题、题注等。格式包不包含项目标题、样例正文或机器绝对路径。

建议新增 v3 清单，格式包使用独立 `format_schema_version`。v1/v2 经适配器生成等价内部规则，保留当前默认输出；无配置项目在本轮升级中也保持原行为。

格式解析顺序固定为“指定预设/父包 → 已保存格式包 → 项目格式覆写 → 命令行覆写”。父包限定单继承并锁定版本，检测循环；不存在的引用直接报错。识别过程只生成候选包，不作为每次构建的隐式配置层。

继续沿用对象递归合并、数组整体替换的规则。新旧格式字段在 v3 中混用时拒绝，而非猜测优先级。导出最终解析配置和每个值的来源；路径以声明文件为基准解析。

### 5.2 格式包的表达范围

| 模型 | 建议字段/能力 |
| --- | --- |
| 元数据 | ID、版本、说明、适用范围、依据、能力清单、资源哈希 |
| 页面与分节 | 纸张、方向、页边距、装订线、镜像边距、页眉页脚距离、栏、文档网格 |
| 字符样式 | 东亚/西文/复杂文字字体、字号、颜色、粗斜体、语言；主题解析与显式字体选择 |
| 段落样式 | 对齐、首行/悬挂缩进、段前后、行距类型、孤行控制、与下段同页、段前分页 |
| 语义角色 | 文档标题、副标题、正文、1—9 级标题、摘要及关键词、题注、引用、列表、参考文献、脚注、表内文字 |
| 结构规则 | 部分顺序、是否入目录、目录层级、章节起页、部件可选性、部分内容来源 |
| 编号 | 多级标题/列表、图表公式编号、附录编号、页码区间与显示形式 |
| 页眉页脚 | 首页/奇偶页变体、链接前节、静态文本与受控域、页码位置及装饰 |
| 保留策略 | 可改写属性、保留区域、局部强调处理、未知对象处理、源目录处理 |

角色注册表允许自定义角色；未知角色必须有明确映射或保留策略。标题层级、可见编号、目录收录是三个独立属性，例如“摘要”可以进入目录而不带章节编号。

单位需要无歧义：页面尺寸用 mm、字号和段距用 pt、字符缩进显式用 char。固定行距与倍数行距使用不同类型，不能混用一个数值；0、false、继承和未识别不能互相替代。内部长度转换使用一致的精度策略。

以下仅为未来格式包示意，**当前 CLI 不接受这些字段**；数值是可修改的演示值，不代表任何学校要求。

```json
{
  "format_schema_version": 1,
  "id": "academic-demo",
  "version": "1.0.0",
  "styles": {
    "body": {
      "run": {"east_asia": "宋体", "latin": "Times New Roman", "size_pt": 12},
      "paragraph": {
        "alignment": "justify",
        "first_line_indent": {"value": 2, "unit": "char"},
        "line_spacing": {"mode": "multiple", "value": 1.5}
      }
    },
    "heading.1": {
      "based_on": "body",
      "run": {"east_asia": "黑体", "size_pt": 16, "bold": true},
      "paragraph": {"keep_with_next": true, "page_break_before": true}
    }
  }
}
```

### 5.3 内容结构的渐进扩展

保留原 DOCX 包和 XML，增加轻量的节点索引与语义注释层，不先把全文转成纯文本再重建。节点包括段落、表格、图、公式、分节和不可拆分对象；定位至少包含源文件哈希、部件 URI、节点身份，不能只使用段落文字。

从现有 `cover/toc/body` 逐步扩展成可排序的具名部分，例如封面、声明、中文摘要、英文摘要、目录、正文、参考文献、附录、致谢。分别记录来源范围、页面规则、编号区间；不强制所有论文使用同一顺序。文件目录层次与源文档标题层次独立，论文导入不能自动把文件名再加成一级标题。

## 6. 样例格式识别

### 6.1 先确定性读取，再判断语义

**读取层。** 解析 OPC 关系、文档默认值、样式及继承、主题字体、编号、段落/run 直接格式、分节、页眉页脚和表格条件样式。支持依赖图、缺失引用与循环检测；有效属性按 OOXML 规则解析，不能简单使用 `paragraph.style.font` 或字典相加代替，包括布尔切换属性等特殊语义。

**统计层。** 仅对实际使用的段落统计格式指纹；区分正文、表格、目录、页眉页脚、文本框等区域。正文候选综合覆盖字符数、段落数、连续分布和所在部分判断；标题候选结合样式/大纲级别、编号、字体、间距、长度和上下文。避免短 run、脚注或参考文献因数量多而主导正文判断。

**映射层。** 证据优先考虑人工映射、可信原生语义、规则和上下文，再用可选模型处理歧义。样式名含“标题”不是充分条件，字号较大也不是充分条件。应考虑手工格式的标题、正文全用 Normal、不同角色同格式、同角色有多种格式，以及目录内重复标题。

**模型层。** 可选模型接收候选角色、精简特征和必要上下文，返回受 schema 约束的候选及理由，不直接生成或修改 OOXML，不凭视觉猜测精确字号。基本样式提取与已保存格式包的构建不依赖模型；模型失败则保留规则候选或交由用户修正。外部模型输入范围应由项目配置明确，避免默认发送整篇论文。

### 6.2 不确定性必须可解释

识别报告按角色及属性记录观察值、来源位置、支持样本数、冲突、缺失项和可靠程度。数值属性读取可靠，不代表角色推断同样可靠；截图推测的字体也不能标为 DOCX 直接读取结果。

初期使用“明确 / 候选 / 待判断”等证据等级。若引入概率分数，需用独立标注样本校准，不能把模型自报的 0.95 当成实测准确率。样例没有三级标题时标为未观察到，可显式继承预设并标注来源。

空白官方模板可读取已定义但未使用的样式，作为另一类候选；写满内容的样例优先采用实际有效格式。样例中的偶然加粗、单页异常边距不能不加判断地推广到全文。

### 6.3 格式包与原生模板配合

JSON 表达可编辑、可验证的常见规则；可选 DOCX 资源保留复杂封面、页眉或表格。原生资源和规则之间必须标明属性所有权：托管区域按规则生成，保留区域按资源复制，不能双方同时定义却没有优先级。

样例提取默认不复制正文、批注、作者和修订历史。确实需要复用带校徽的封面时，作为独立资源显式选择和预览。只读解析不执行宏、不访问外部关系；限制压缩包解压体积和 XML 解析资源，防止损坏输入拖垮分析。

PDF/扫描件识别放到后续：页面图像难以恢复样式继承、精确字体、自动编号和分节意图，只能生成带不确定性的近似候选，不能承诺一键精确复刻。

## 7. 应用与验收机制

### 7.1 一个样式应用通路

新增统一的格式应用器，生成具名 Word 样式，为已识别段落设置样式和大纲级别。原生样式 ID 按来源重映射；目标托管样式与保留源样式分开命名。可以借鉴 `composition.py` 已有重映射实现，但需补全并验证依赖与主题处理，不能直接假定覆盖所有对象。

受目标规则管理的直接格式应按属性清理，否则会遮蔽目标样式；明确保留斜体强调、上下标、链接、字段、数学对象等语义信息。不要删除整段 run 再写回纯文本。字体缺失必须在预检中显示；严格排版要求下禁止静默替换字体。

文字清洗、黑色化、去页码、自动修正行距、移除空段和材料专项规则均改为显式策略。旧规则只由兼容预设启用。PDF/图片尺寸和目录制表位由当前节版心推导；页码清除与空白裁切也纳入策略及缓存键。

保留完整 OPC 关系闭包及 ID 重映射，覆盖编号、书签、脚注/尾注、媒体和跨段字段。无法可靠处理的对象给出定位及保留或阻止重排的结果，不能静默删掉。首版复杂对象仍需明确能力边界。

### 7.2 论文分页与目录

将页码记录扩展为物理页、节/编号区间、编号数值、显示标签，例如物理第 5 页对应标签 `III`。显示标签与数值分开，封面隐藏页码与不计数也分开配置。

Word 的 adjusted page number 是编号数值，不能直接证明实际显示为罗马数字。对支持的编号形式从节规则生成预期标签，再与 Word 更新后字段/PDF 实际结果核验；读取后端的可行性先做技术验证。目录仍使用稳定书签身份，允许同名标题与不同区间相同编号。

保留现有有限次回填与收敛机制。多种交付结构若影响节起始奇偶性或正文几何尺寸，不能无条件复用同一份已排版正文；可复用内容中间层，按兼容的版面配置分组排版。

源目录显式选择保留、移除或重建。重建只处理已确认的目录区域及标题映射；原生 TOC、SEQ、REF、STYLEREF 等字段需要专门的更新顺序和验证。重新分页不等于更新所有字段，首版也不能宣称已校验源目录。

### 7.3 分层检查

- 配置与能力检查：单位、引用、继承、有效版心、字体、所需功能支持情况；`--plan` 展示解析后的格式、覆盖范围和未决映射，保持只读、不调用 Office/模型/网络。
- 结构与内容检查：正文文本不丢失，图片/表格/公式/脚注关系保留，字段与书签完整，样式引用可达。按对象结构核验，不能只靠总字数。
- 格式检查：基于解析后的有效属性验证角色规则，抽查混合文字、列表与表格条件样式，不仅检查样式定义存在。
- Word 实际排版检查：分节编号、目录跳转、字段显示、溢出、裁切、孤行；按格式包标记允许的空白页和章节扉页。
- 视觉检查：代表页覆盖封面、目录、各级标题、普通正文、图表、公式、横版和节边界。HTML 仅是交互预览，Word 导出的页面才是本项目版面验收依据。

发布继续使用隔离目录、全部交付物通过后替换和失败回滚。预览稿明确标注尚未完成 Word 验收。

## 8. 实施顺序与完成条件

| 阶段 | 工作与建议模块 | 可验收结果 |
| --- | --- | --- |
| P0：兼容基线与技术验证 | 清点格式写入点；建立匿名边界样本；验证样式有效值解析、复杂对象保留、罗马页码读取 | 记录支持矩阵和限制，锁定旧示例结构与 Word 版面基线；验证失败项调整范围 |
| P1：自定义格式基础 | `format_schema.py`、`format_resolver.py`、`style_applier.py`；改造 config/styles/renderers/highlighted 路径；提供兼容与通用报告预设 | 同一内容仅换格式包即可改变标题、正文、目录和页面；后续步骤不覆盖设置；Word 导航与样式编辑有效 |
| P2：样例识别闭环 | `docx_inspector.py`、`role_mapper.py`；统一入口分析操作；候选报告、校正映射、格式包保存与预览 | 从原生样式和手工格式两类 DOCX 提取规则，经校正应用到另一文件；保存后无需重新识别即可复现 |
| P3：完整学位论文基础 | 部分与分节模型；升级 composition/pagination/delivery/qa；题注、原生编号、脚注及受控字段处理 | 匿名论文包含双语摘要、罗马前置编号、阿拉伯正文编号、图表与附录；目录、字段和对象保留通过真实 Word 验收 |
| P4：扩展能力 | 图形化选择与编辑、多个样例融合、PDF/OCR、双栏期刊、专业格式包 | 按独立场景逐项验收；不把未验证能力放入通用承诺 |

依赖关系为 P0 → P1 → P2；P3 的模型接口在 P1 预留，实现可在基础格式稳定后推进。**首个对外可用版本以 P1＋P2 为边界**，覆盖自定义格式和样例学习；完整论文支持以 P3 验收为准。

建议首批变更拆成：配置契约与兼容适配、统一格式应用与策略隔离、样例读取与角色映射、校正预览与复用、论文结构与分页。每批都有独立验收，避免一次替换整个渲染器。具体工期在 P0 技术验证后估算。

## 9. 验收样本与指标

使用匿名或许可明确的 DOCX；不把业务材料加入公开测试集。最低样本集覆盖：标准样式文档、全手工格式、混用样式、多来源同名样式、空白模板、中西文混排、1—9 级标题、多节横版、复杂表格、公式、脚注、字段、重复标题和未知对象。

建议门槛如下，属于待实现目标，不是当前成绩：

- 支持范围内的确定性格式提取，对标注的结构样本逐项一致；单位按明确转换精度比较。
- 角色识别按类别统计 precision/recall、待判断比例与人工修正次数；在独立测试集评估。可先以自动接受的标题候选精确率不低于 98% 为发布目标，同时报告覆盖率，避免靠全部弃权达标。
- 基准样本中的受保护文本、公式、脚注、图片和内部引用零非预期丢失；发现无法保留的对象必须阻止相应重排或进入用户选择的保留流程。
- 相同输入、格式包、映射和渲染环境产生等价样式与分页；记录依赖、Word、字体版本及输入/格式包哈希，不要求 DOCX ZIP 字节完全相同。
- 旧匿名示例和 v1/v2 配置保持既有语义及版面基线；新正文仅修改格式包即可得到两套确实不同且通过验收的版式。
- 单元测试验证继承、直接格式覆盖、主题、多级编号及配置错误；Word 集成测试验证真实分页和字段；视觉检查验证代表页面。离线测试不能替代 Word 验收。

## 10. 需要明确保留的范围边界

首版不承诺任意 PDF 还原为可编辑 Word、不重写论文内容、不自动核实或改写参考文献著录内容、不覆盖所有期刊规范。参考文献段落的字体缩进属于排版；文献数据解析、CSL 样式和著录规则应作为独立能力接入。

当前规划不依赖新增模型服务或更换整套文档引擎。最先值得实施的是格式契约和统一应用通路；样例识别得到的规则只有通过这条通路，才能稳定覆盖正文、标题和后续更多用途。
